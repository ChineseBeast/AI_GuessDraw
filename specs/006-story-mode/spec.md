# Feature Specification: 故事模式

**Feature Branch**: `dev-gd`

**Created**: 2026-08-08

**Status**: Approved for implementation

**Input**: 用户希望开始完成故事模式，并继续采用 Spec-Driven Development。

## 概述

故事模式是一段由绘画推动的三章互动冒险。玩家先选择主题，阅读章节剧情并完成绘画任务；系统评价画作、给出星级反馈，并依据评价结果生成不同的剧情衔接与最终结局。

MVP 提供奇幻、太空、海底三个主题。进度保存在服务端内存中；AI 服务不可用时必须自动降级为本地剧情与启发式评价，保证完整流程仍可游玩。

## User Scenarios & Testing

### User Story 1 - 开始一段主题冒险 (Priority: P0) 🎯 MVP

玩家从首页进入故事模式，选择一个主题后立即获得三章故事，并进入第一章。

**Why this priority**: 没有稳定的故事创建和章节结构，后续绘画与分支均无法成立。

**Independent Test**: 从首页点击故事模式，选择任一主题，看到故事标题、第一章剧情和绘画任务。

**Acceptance Scenarios**:

1. **Given** 玩家位于首页，**When** 点击故事模式，**Then** 系统展示奇幻、太空、海底三个主题。
2. **Given** 玩家选择主题，**When** 故事创建成功，**Then** 系统展示第一章且仅第一章处于解锁状态。
3. **Given** AI 服务无法访问外部模型，**When** 玩家开始故事，**Then** 系统仍使用内置模板返回可玩的三章故事。

---

### User Story 2 - 用绘画推进剧情 (Priority: P0) 🎯 MVP

玩家阅读当前章节的绘画任务，在共享画布上作画并提交；系统评价画作，展示分数、星级、反馈和剧情结果，然后解锁下一章。

**Why this priority**: 绘画驱动剧情是故事模式区别于普通文字冒险的核心体验。

**Independent Test**: 在第一章绘制至少一笔并提交，能够获得评价且进入第二章。

**Acceptance Scenarios**:

1. **Given** 当前画布为空，**When** 玩家尝试提交，**Then** 系统阻止提交并提示先完成绘画。
2. **Given** 当前画布有内容，**When** 玩家提交，**Then** 系统返回 0-100 分、1-3 星、反馈和分支剧情。
3. **Given** 当前章节评价完成，**When** 玩家点击继续，**Then** 下一章解锁并保留累计得分。
4. **Given** 外部 AI 识别失败，**When** 玩家提交有效画作，**Then** 系统使用降级评价并正常解锁下一章。

---

### User Story 3 - 完成冒险并获得结局 (Priority: P1)

玩家完成第三章后看到与累计表现对应的结局、总分和各章星级，并可重新开始另一主题。

**Why this priority**: 明确的结局和复玩入口让三章流程形成闭环。

**Independent Test**: 连续完成三章，看到结局页，并可返回主题选择重新开始。

**Acceptance Scenarios**:

1. **Given** 玩家完成第三章，**When** 评价返回，**Then** 故事状态变为 completed 并生成结局。
2. **Given** 玩家位于结局页，**When** 查看冒险回顾，**Then** 能看到总分和三章评价。
3. **Given** 玩家位于结局页，**When** 选择再玩一次，**Then** 返回主题选择且旧故事不影响新故事。

### Edge Cases

- 主题值不在允许列表时返回 400，不创建故事。
- 故事 ID 不存在时返回 404。
- 提交未解锁章节、已完成章节或非当前章节时返回 409。
- 图片为空、不是 data URL、超过 5MB 时返回 400。
- AI 调用超时或返回无效结构时使用降级评价，而非中断冒险。
- 重复点击提交时前端锁定按钮，服务端也拒绝重复章节提交。
- 页面刷新后，MVP 不自动恢复故事；服务端 GET 进度接口为后续恢复能力提供基础。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 提供 fantasy、space、underwater 三种故事主题。
- **FR-002**: 系统 MUST 为每个新故事生成恰好 3 个有序章节。
- **FR-003**: 每章 MUST 包含标题、叙事、绘画任务、关键元素提示和解锁/完成状态。
- **FR-004**: 系统 MUST 复用 `@draw-guess/ui` 的 Canvas 组件完成绘画。
- **FR-005**: 前端 MUST 阻止空画布提交，并在请求期间阻止重复提交。
- **FR-006**: 系统 MUST 对有效画作返回 0-100 分、1-3 星、反馈、识别元素、评价模式和分支类型。
- **FR-007**: 分支类型 MUST 为 positive、neutral、alternative 之一，并用于生成章节衔接文本。
- **FR-008**: 完成一章后系统 MUST 解锁下一章并更新累计得分。
- **FR-009**: 完成第三章后系统 MUST 返回结局并将进度标记为 completed。
- **FR-010**: NestJS 服务 MUST 提供开始故事、提交章节和查询进度接口。
- **FR-011**: FastAPI 服务 MUST 提供生成故事和评价画作接口。
- **FR-012**: 外部模型不可用时 FastAPI MUST 返回本地降级结果，且明确 `evaluationMode=fallback`。
- **FR-013**: 服务端 MUST 验证主题、章节顺序和图片大小。
- **FR-014**: MVP MUST 支持游客使用，不强制登录。
- **FR-015**: MVP MUST 使用内存保存故事进度，不引入数据库。

### Key Entities

- **StoryProgress**: 一次故事冒险，包含主题、状态、当前章节、累计得分、章节和画作评价。
- **StoryChapter**: 一个有序章节，包含叙事、绘画任务、关键元素与完成状态。
- **StoryDrawing**: 玩家在某章提交的画作快照及其评价。
- **DrawingEvaluation**: 画作的分数、星级、反馈、分支和评价模式。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 玩家可在不登录的情况下从首页进入故事模式并开始任一主题。
- **SC-002**: 玩家可连续完成 3 章并到达结局，流程中无死路。
- **SC-003**: 每次有效提交均在 15 秒内获得 AI 或降级评价；降级路径在 1 秒内返回。
- **SC-004**: AI 服务断开或密钥无效时，开始故事与提交画作仍返回成功响应。
- **SC-005**: 前端生产构建、后端构建和故事核心单元测试全部通过。
- **SC-006**: 浏览器验收覆盖主题选择、章节绘画、评价、继续和结局入口。

## Assumptions

- 每次冒险固定为 3 章，MVP 不支持自定义章节数。
- 故事进度在服务进程重启后丢失，持久化留给后续版本。
- 画作以 PNG data URL 在服务间传输，单张原始图片不超过 5MB。
- 默认且唯一的前端 AI provider 为 minimax（MiniMax-M3）；不展示模型选择页，模型失败时自动降级，不要求玩家手动重试。
- 小程序端本期只共享类型与接口契约，不实现页面。

## Out of Scope

- 数据库持久化、跨设备续玩和故事历史列表。
- 多人协作故事、故事分享和图片云存储。
- 用户自定义主题、无限章节和付费内容。
- 小程序故事页面。
